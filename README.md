# fictional-pennant

架空12球団のペナント専用ブラウザゲーム。画面は **Phase 1.5**（球団選択・複数セーブ・UI改善）、内部データは **Phase 2A**（選手モデル・架空選手生成）まで実装しています。選手データの画面表示とセーブへの統合はPhase 2Bで行います。

## 開発

Node.js 22.12以上（確認環境：24.22.1）、npmを使用します。

```sh
npm ci
npm run dev
```

Viteが表示するURLをブラウザで開いてください。スマートフォンでも同じサーバーへアクセスできます。保存先はアクセスしたオリジンごとのIndexedDBです。

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

ブラウザテスト（スマートフォン縦画面・PC）：

```sh
npx playwright install chromium
npm run test:e2e
```

クラウド環境の既存Chromiumを使う場合（ダウンロード不要）：

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

npmキャッシュは書き込み可能なチェックアウト内の `.npm/`（Git対象外）を使用します。

## 手動確認

1. ホームで両リーグ各6球団を確認します。未選択では開始ボタンを押せません。
2. 球団を選んで「この球団で始める」を押します。操作球団とスロットが表示されます。
3. ページを再読み込みし、球団とスロットが復元されることを確認します。
4. 「新しいスロットで始める」で別の球団を選択します。元のセーブを残して2つ目が作成されます。
5. 元のスロットを読み込み、操作球団が元に戻ることを確認します。「手動保存」は同じスロットを更新します。
6. 下部の5メニューを操作し、未実装画面に「準備中」が表示されることを確認します。
7. スマートフォン縦画面でも横スクロールせず操作でき、下部メニューが固定されることを確認します。

## 構成と今回の範囲

- `src/data/teams.ts`：確定した球団名・所属とカラーの初期案。具体的なカラー値は表示上の仮定です。
- `src/game/save.ts`：バージョン付きのセーブ型・作成・検証。
- `src/storage/saves.ts`：IndexedDB。新規セーブと現在スロットの選択を同一トランザクションで保存し、完了後にUIへ反映します。保存操作では操作球団を変更できません。
- `src/App.tsx`、`src/style.css`：日本語UI、球団選択、保存・読み込み、固定メニュー。
- `src/game/players/`、`src/game/random/`：UI・保存から独立した選手モデル、12球団の生成、シード付き乱数。仕様と暫定値は [選手生成の説明](docs/player-generation.md) を参照してください。
- `src/test/`、`e2e/`：生成データの整合性と保存処理・ブラウザでの回帰テスト。

スロット数に固定上限は設けていません（ブラウザの保存容量に依存）。ゲーム内の日付・年度はこのフェーズでは定義しません。表示する日時は実際の保存日時です。

選手モデル・個別能力・架空選手生成は内部モジュールとして実装済みです。試合、日程生成、育成・故障の計算、ドラフト・FA・トレード・契約交渉は未実装です。試合結果・順位・選手成績のダミー表示はありません。Service Workerによるオフライン配信、JSON入出力、セーブ形式移行も後続フェーズの対象です。

セーブはこの端末のブラウザ内に保存されます。ブラウザデータの削除で失われます。未対応・破損した保存形式は上書きせずエラーにします。

確定仕様は [要件定義書](docs/requirements.md)、実装計画は [開発計画](docs/development-plan.md) を参照してください。
