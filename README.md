# fictional-pennant

架空12球団のペナント専用ブラウザゲーム。**Phase 2D**まで実装しています。球団選択前のプレビュー、912人の選手を含む複数セーブ、旧形式の安全な移行、保存済み選手の一覧・能力・過去成績・契約の閲覧に対応しています。全球団の名前検索・絞り込み・個別能力順の比較に対応しています。表示仕様・検証・画像は [選手検索の説明](docs/player-search.md) と [選手詳細の説明](docs/player-screens.md) を参照してください。

## 開発

Node.js 22.12以上（確認環境：24.22.1）、npmを使用します。

```sh
npm ci
npm run dev
```

Viteが表示するURLをブラウザで開いてください。スマートフォンでも同じサーバーへアクセスできます。保存先はアクセスしたオリジンごとのIndexedDBです。

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

ブラウザテスト（スマートフォン縦画面・PC）：

```sh
npx playwright install chromium
npm run test:e2e
```

クラウド環境の既存Chromiumを使う場合（ダウンロード不要）：

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

npmキャッシュは書き込み可能なチェックアウト内の `.npm/`（Git対象外）を使用します。

## 手動確認

1. ホームで両リーグ各6球団を確認します。選手世界の準備中・未選択では開始ボタンを押せません。「球団選択前に選手を確認」を開き、表示球団を切り替えて選手を確認できます。
2. 球団候補を選んで再読み込みし、同じ候補・選手世界が残ることを確認します。「この球団で始める」を押すと、その世界と操作球団が同じスロットに保存されます。
3. ページを再読み込みし、球団とスロットが復元されることを確認します。
4. 「新しいスロットで始める」で別の球団を選択します。元のセーブを残して2つ目が作成されます。
5. 元のスロットを読み込み、操作球団が元に戻ることを確認します。「手動保存」は同じスロットを更新します。
6. 下部の「選手」で自球団と全球団を切り替え、名前・詳細条件で検索し、年齢や個別能力で並べ替えます。選手をタップして能力・成績・成長・契約のタブを確認します。成長記録と他の未実装画面は「準備中」です。
7. スマートフォン縦画面でも横スクロールせず操作でき、下部メニューが固定されることを確認します。

## 構成と今回の範囲

- `src/data/teams.ts`：確定した球団名・所属とカラーの初期案。具体的なカラー値は表示上の仮定です。
- `src/game/save.ts`：schemaVersion 2のセーブ型・作成・検証。旧v1の移行方法と物理形式は [セーブ形式の説明](docs/save-format.md) を参照してください。
- `src/storage/saves.ts`：IndexedDB。選手世界・メタデータ・現在スロットの選択を同一トランザクションで保存し、完了後にUIへ反映します。一覧は小さいメタデータだけを読みます。保存操作では操作球団を変更できません。
- `src/App.tsx`、`src/style.css`：日本語UI、球団選択、保存・読み込み、固定メニュー。
- `src/game/players/search.ts`：公開DTOだけで検索・AND条件・個別能力順の比較を行う純粋処理。
- `src/components/players/`、`src/storage/playerViews.ts`：保存済みの公開DTOを使う選手一覧・タブ式詳細。
- `src/game/players/`、`src/game/random/`：UI・保存から独立した選手モデル、12球団の生成、シード付き乱数。仕様と暫定値は [選手生成の説明](docs/player-generation.md) を参照してください。
- `src/test/`、`e2e/`：生成データの整合性と保存処理・ブラウザでの回帰テスト。

スロット数に固定上限は設けていません（ブラウザの保存容量に依存）。ゲーム内の日付・年度はこのフェーズでは定義しません。表示する日時は実際の保存日時です。

選手モデル・個別能力・架空選手生成は実装済みで、選択前の簡易プレビュー、セーブ、保存済みデータの一覧・詳細へ接続しています。試合、日程生成、育成・故障の計算、ドラフト・FA・トレード・契約交渉は未実装です。試合結果・順位・選手成績のダミー表示はありません。Service Workerによるオフライン配信、JSON入出力は後続フェーズの対象です。旧セーブのv1→v2移行は読み込み時に実施します。

セーブはこの端末のブラウザ内に保存されます。ブラウザデータの削除で失われます。未対応・破損した保存形式は上書きせずエラーにします。

確定仕様は [要件定義書](docs/requirements.md)、実装計画は [開発計画](docs/development-plan.md) を参照してください。

Phase 2A〜2Dの検証結果と残課題は [最終確認](docs/player-search.md#phase-2a2dの最終確認) を参照してください。1軍登録の所属モデル・31人制約は未実装で、Phase 3の起用・試合への接続時に検討が必要です。
