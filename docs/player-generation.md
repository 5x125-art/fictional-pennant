# Phase 2A：選手モデルと初期生成

この文書はPhase 2Aの生成モジュールについての記録です。Phase 2Bでの保存統合は [セーブ形式と移行](save-format.md) を参照してください。

Phase 2Aの実装時点では内部データのみです。UI、`GameSave`（schemaVersion 1）、IndexedDBのスキーマ・保存処理は変更していません。既存のセーブを削除・移行・上書きする処理も追加していません。

## 使用方法

```ts
import { generateInitialPlayerWorld } from '../src/game/players/generate';
import { abilityRank } from '../src/game/players/rank';
import { SeededRandom } from '../src/game/random/seededRandom';

const world = generateInitialPlayerWorld(20261114);
// world.players: 12球団・計912人の公開可能な現在能力・契約・過去成績
// world.developmentByPlayerId: 非公開の成長タイプ・能力別上限
// world.phase: 'awaitingClubSelection'（操作球団は未選択）
abilityRank(85); // 'A'（0〜100系のみ）
const simulationRng = new SeededRandom(world.randomState); // 生成後の乱数列を再開
```

同じ生成コード・設定・32bit符号なし整数シード（0〜4294967295）なら、ID、選手、非公開情報、過去成績、生成後の乱数状態まで一致します。時刻、`Math.random()`、ブラウザ、IndexedDBに依存しません。乱数方式はMulberry32で、将来の試合・育成からも使える独立モジュールです。認証や秘密情報の生成には使用しません。

IDはシードと世界内の連番から生成します。同じ世界の中で一意です。同一シードの別世界とのID共有は意図した再現性であり、将来の保存ではセーブ／世界の単位で扱います。

Phase 2Bでは新規ゲーム開始時に一度だけシードを用意して**この結果を保持**し、公開選手一覧を見せてから操作球団を選択します。球団を選ぶたびに生成関数を呼び直してはいけません。今回のモデルは操作球団IDを持たず、この選択前データに対応しています。実際のリロール防止・セーブ統合・旧形式の移行はPhase 2Bで実装しました。

## データの分離

- `types.ts`：投手／野手の判別可能な型、年度別成績、選択前の世界。
- `generate.ts`：全12球団の生成。総合能力を作らず、個別能力ごとに抽選します。
- `generationConfig.ts`：人数構成・確率・分布・名前候補・ランク境界などの暫定値。登録上限70／10は確定仕様です。
- `history.ts`：架空の完了年度成績。試合シミュレーションではありません。
- `names.ts`：世界ごとの名前専用乱数と、重複なし・姓の出現回数を均等にする姓名生成。
- `rank.ts`：0〜100系能力の共通S〜G変換。不正値を拒否します。
- `random/seededRandom.ts`：シード、整数抽選、候補選択、状態取得・復元。

`Player`は現在能力・守備適性・契約・体力・調子・経歴・過去成績を持ちます。投手と野手は別の型で、二刀流は定義しません。投手は球速・制球・スタミナ・先発／救援適性・役割・球種ごとの球威／制球／変化量を持ちます。野手は対右／対左ミート・パワー・弾道・走力・盗塁・捕球・スローイング・肩力・8守備位置の適性を持ちます。

`PlayerDevelopment`は別のID辞書で保持します。成長タイプと現在能力に対応した個別成長上限を持ち、UIには渡さない想定です。守備位置の習得に選手固有の上限を設けない仕様に従い、**守備適性の個人別成長上限は持ちません**。総合能力値、分野別総合ランク、特殊能力、捕手リード、顔画像も持ちません。

## 選手名の一意性と多様性

日本人名は姓148種・名109種（組み合わせ16,132通り）、外国人名は姓・名各32種（1,024通り）です。候補は`generationConfig.ts`の`namePools`で管理します。

世界ごとに名前専用のシード付き乱数系列を作り、姓の順序をシャッフルして一巡ずつ使用します。各姓に組み合わせる名もシャッフルして重複なしで消費します。初期世界の日本人864人では各姓5〜6回、外国人48人では各姓1〜2回となり、全912人のフルネームが一意になります。候補数は有限で、使い切った場合は重複や番号付加で代用せずエラーにします。

今回の名前改善では、旧姓名抽選に使っていた2回分の乱数消費を既存の生成系列に残しています。名前用のシャッフル回数が変わっても能力・契約・経歴・非公開情報・ID・生成後の乱数状態は変わりません。修正前コミット`ea45960`との名前以外の全データ比較を4シードで検証しています。新しい名前についても6シードで全員の重複なし・姓の均等性・完全再現性を確認しています。既存のセーブ内の名前を書き換える処理はありません。

## 単位と経歴

- 基本能力・守備適性・先発／救援適性・体力：0〜100の整数。
- 球速：km/h。弾道：1〜4。球種変化量：0〜7。これらにS〜G変換は適用しません。
- 年俸：万円／年。初期契約は全員1年。
- プロ在籍年数：現在シーズンの開始時点で完了済みのシーズン数。育成期間も含めます。
- 過去成績の`season`：現在を0とする相対年度で、過去は-1、-2…です。実暦の開始年度は未確定のため追加していません。
- 成績の`age`：年度開始時の年齢。入団年齢から現在年齢の前年までを1年ずつ生成します。新入団選手は過去成績が空です。
- 過去成績は1軍と2軍を分けて保存。育成年度は1軍の全項目が0。投球回は誤差のない整数のアウト数（`outs`）で保持します。

現段階の経歴は、外国人を含めて日本の現在所属球団での在籍のみを生成する簡易モデルです。海外リーグや過去の移籍・契約履歴は追加していません。そのため完了済みの日本在籍年数とプロ在籍年数は同じ値です。両項目は今後のFAと外国人枠免除の別々の計算に備えて分離しています。これは簡略化した生成上の仮定で、外国人の日本適応能力やペナルティを追加するものではありません。

## 暫定値（ゲームの確定仕様ではない）

|---|---|
| 人数 | 1球団 支配下68＋育成8。支配下は投手34／野手34、育成は投手4／野手4 |
| 守備構成 | 支配下野手は捕手6、他7位置各4。育成野手は捕手・遊撃・中堅・一塁各1 |
| 投手役割 | 支配下：先発16・中継ぎ10・セットアッパー3・抑え2・ロング3。育成：先発2・中継ぎ1・ロング1 |
| 外国人 | 各球団4人（支配下の投手2・野手2）。初期生成用の指定枠であり、将来の獲得人数制限ではない |
| 年齢 | 支配下18〜40歳、育成18〜25歳、外国人24〜36歳。一様抽選 |
| 入団年齢 | 高卒18・大卒22・社会人24・独立20・外国人22。現在年齢以下の経歴候補から選択 |
| 投打 | 左投げ26%。左打ち34%・両打ち5%・右打ち61%。捕手・二遊間・三塁は右投げのみ |
| 基本能力 | 36〜76の抽選に±15、育成-14、23歳未満-5、球団別の小補正を加えて0〜100に収める。35歳以上の走力は追加-12 |
| 球団差 | 打撃／投手の個別能力へそれぞれ-3〜+4／-3〜+3の補正。都市規模と無関係で、選手の総合値は生成しない |
| 守備適性 | 主守備60〜95、関連する副守備は35%で25〜60、他は0。左投げの内野適性も整合させる |
| 球速・球種 | 球速125〜165km/h、初期球種3〜5（重複なし、直球を含む）。球種配列に将来の習得数の固定上限は設けない |
| 成長タイプ | 早熟25%・標準50%・晩成25%。実際の成長計算は未実装 |

| 体力・調子 | 体力90〜100。調子は5段階、普通の重み3、他各1 |
| ランク | S90〜100、A80〜89、B70〜79、C60〜69、D50〜59、E40〜49、F30〜39、G0〜29 |
| 年俸 | 育成240万円。支配下500万円＋完了済みプロ在籍年数×100万円＋前年1軍実績による加算。野手は安打×15＋本塁打×150、投手はアウト数×4＋奪三振×10（各万円） |
| 過去成績 | 1軍143試合・2軍110試合以内。野手は合計143出場以内、先発は1軍＋2軍計26登板以内、救援は計60以内。育成開始期間0〜3年、現育成は全過去年育成扱い |

成績係数の詳細（打率.180〜.320、四球率.04〜.13、投手のアウト数当たり失点.07〜.20など）は設定の`history`へ集約しています。個人内の打席・安打内訳・自責点等の整合性を保つための初期データであり、リーグ全体の得点と打点、対戦相手同士の実績を突き合わせた架空試合履歴ではありません。成績は現在能力や成長タイプを逆算して公開するものでもありません。

## 検証と手動確認

```sh
npm run typecheck
npm test
npm run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

型チェック・自動テスト56件・本番ビルド・ブラウザテスト6件はすべて成功しています。

生成テストは全12球団の人数・ID・守備構成、能力範囲と上限、年齢・経歴と成績の整合性、ランク境界、乱数の状態復元、同一／別シード、球団差、禁止フィールドの不在を確認します。Phase 1の保存処理・UUID代替・ブラウザ操作も回帰テストします。

手動では`npm run dev`から従来どおり球団選択・新規スロット・手動保存・スロット切り替え・再読み込みを確認できます。選手の詳細画面は引き続き「準備中」です。Phase 2Bでは新規ゲーム用の簡易プレビューと保存統合を追加しています。
