# Phase 3B-1：走者プレー（engineVersion 2）

Phase 3Aの単体試合エンジンへ併殺・犠飛・成功犠打を追加しました。以下のPhase 3A節は比較用の旧仕様・旧実行結果です。現在の差分はこの節を優先してください。UI・セーブv3・IndexedDB・既存選手情報は変更していません。

## プレーと成績

`PlateAppearanceOutcome`に`groundDoublePlay`、`sacrificeFly`、`sacrificeBunt`を追加しました。`outcomes`は基礎9結果の列挙を維持し、全対応結果は`playOutcomes`で取得します。

`advanceRunners(bases, batterId, outcome, runsToWin?, outsBefore = 0)`は従来フィールドに加え`outsRecorded`と`movements`を返します。各移動は選手ID、出発位置（打者0／一〜三塁1〜3）、到着位置（1〜3／score／out）、アウト種別（batter／force）を保持します。動かない走者も同じ塁への移動として記録し、打者と全走者をそれぞれ1回ずつ表します。同じフィールドを打席イベントにも格納します。投手アウト数は打者アウトの真偽ではなく`outsRecorded`から加算します。

| 結果 | 成立条件 | 決定的な処理 |
|---|---|---|
| ゴロ併殺 | 0〜1アウト・一塁走者あり | 一塁走者のフォースアウト→打者アウト、計2アウト。他走者は保持、得点・打点なし。打数に含む |
| 犠牲フライ | 0〜1アウト・三塁走者あり | 打者アウト、三塁走者だけ生還。他走者保持。犠飛・1打点・得点を記録し、打数から除外 |
| 成功犠牲バント | 0〜1アウト・一塁または二塁走者あり・三塁は空 | 打者アウト、一・二塁走者が1塁進む。犠打と投手アウトを記録し、打数から除外。得点・打点なし |

スクイズは未実装です。三塁走者がいる状況の`sacrificeBunt`（満塁・一死三塁などを含む）は明示的に例外で拒否します。対象走者なし・2アウトの新結果注入も例外とし、通常アウトへの暗黙の置換はしません。第3アウトに達する併殺で得点や次打席を追加しません。犠飛・犠打のアウトは第3アウトにならず、サヨナラも従来どおり9〜12回裏の勝越点で直ちに終了します。高度な併殺経路・走塁判断・タッチアップ失敗は未実装です。

個人得点・打点・投手失点・イニング得点は共通の得点者列から計上します。現在のプレー集合では打点合計＝得点合計と、打席数＝投手アウト数＋得点＋全半イニング残塁人数が引き続き成立します（併殺は前打席の走者をアウトにするため）。今後の盗塁・失策などにはそのまま一般化できません。

## 暫定確率と再現性

`outcomeProbabilities`と`drawPlateAppearance`の末尾引数へ任意の`{outs, bases}`を追加しました。未指定なら従来の基礎9結果を返します。試合では毎打席の状態を渡します。`runnerPlayConfig`で対象ゴロの35%を併殺、対象フライの65%を犠飛へ振り分けます。安打・四死球・三振の1打席確率は変更せず、合計1を維持します。犠打の抽選確率は常に0で、`resolvePlateAppearance`による固定結果注入だけが入口です。采配AIや犠打失敗は含みません。

追加の乱数抽選は行わず、従来の結果抽選に確率を割り当てます。ただし結果・打席数の変化により後続の乱数消費が変わるため、Phase 3Aと試合結果の完全一致は保証しません。`engineVersion`は2に更新し、同じ入力・シード・版では完全再現します。保存形式の版は変更しません。

# Phase 3A：打席単位の単体試合エンジン

`src/game/match/`に、React・IndexedDB・実時間から独立したTypeScriptの試合計算を実装しました。既存のschemaVersion 3、DB構造、選手生成、所属、画面は変更していません。結果は呼び出し元へ返すだけで、日付・正式乱数・選手・今季成績・セーブへ反映しません。

## API

```ts
import { simulateMatch, type MatchInput } from "../src/game/match";

const input: MatchInput = {
  // 呼び出し元で検証・読込済みの選手と所属。engineは保存APIを呼ばない。
  players: save.world.players,
  roster: save.world.roster,
  away: {
    teamId: awayTeamId,
    availablePlayerIds: awayBenchIds, // 明示した当日の出場可能選手
    battingOrder: awayOrder,         // [{playerId, position}, ...] 配列順に1〜9番
    startingPitcherId: awayStarterId,
  },
  home: {
    teamId: homeTeamId,
    availablePlayerIds: homeBenchIds,
    battingOrder: homeOrder,
    startingPitcherId: homeStarterId,
  },
  seed: matchSeed, // 明示した試合専用uint32。正式保存のPRNGを進めない。
};
const result = simulateMatch(input);
```

コード例の`save`などは呼び出し元の変数で、今回UIや保存処理へ接続するコードは追加していません。全12球団の所属整合を既存関数で検証するため、`players`は所属一覧を検証できる全選手データを渡します。試合で利用できる人数は各球団の`availablePlayerIds`で別に限定します。

- `validateMatchInput(unknown)`：不正なら`MatchInputError`。選手の計算対象能力・投打・球種の整数範囲、所属状態、同一球団対戦、ベンチ・打順・守備・先発を同期検証します。正式セーブ全体の検証・移行を代行しません。
- `simulateMatch(input, options?)`：1試合を計算し、完了した`MatchResult`だけを返します。途中状態を保存しません。
- `options.resolvePlateAppearance(context)`：規則テスト用の結果注入。未指定時は能力と`SeededRandom`で抽選します。注入関数は決定的にし、未実装の結果を返すと例外です。
- `outcomeProbabilities(batter, pitcher, pitch)`：検証済みの現在能力と選択球種から9結果の確率を計算する純粋関数。
- `drawPlateAppearance(batter, pitcher, random)`：呼び出し側から渡した試合用PRNGを使用。
- `advanceRunners(bases, batterId, outcome, runsToWin?)`：塁ID配列のコピー、得点者ID、実際の安打種別、打者アウトを返す純粋な進塁処理。

注入コールバックにはホワイトリストでコピー・凍結した現在能力と打席前状態だけを渡します。元のPlayer、契約、過去成績、所属辞書、非公開成長情報は渡しません。打席結果を注入した場合も推定球数には試合用PRNGを使用します。

## 入力の制約

- 両球団は固定12球団の異なる2球団。
- ベンチは既存の`validateBench`を利用し、1軍・支配下・人数・外国人枠・重複・所属を検証します。
- 打順は欠員・重複のない野手9人。8守備位置（C/1B/2B/3B/SS/LF/CF/RF）とDHを各1人。投手は別に1人指定します。
- 打者も投手も当日の出場可能IDに含まれる自球団の選手。2軍・育成は起用不可。
- 位置ごとの適性0を拒否し、1以上を許可する境界は**暫定設定**です。主守備位置以外でも適性があれば許容し、DHに守備適性は不要です。
- 自動スタメン・ベンチ選定はありません。テストだけで、1軍登録者から各位置を明示した固定打順を用意します。

## 確定ルールと試合状態

9回制、両リーグDH、3アウト交代、打順継続、同点なら延長12回まで。12回裏終了時同点は引き分けです。延長の自動二塁走者は置きません。

9回表終了時に後攻がリードしていれば9回裏は未実施とします。9回裏以降は後攻の勝越点で直ちに終了します。先攻リード・同点なら必要な裏を行い、12回裏も同じ規則を適用します。追いついた点だけでは終了しません。

`Situation`は回、表裏、アウト、塁上の選手ID、先後攻得点、両軍の次打者インデックス（0〜8）を保持します。ログの打順番号は1〜9です。攻守交代時だけアウトと塁をリセットし、両軍の打順を保持します。

`finalState`は最終打席直後の状態です。最終アウト後の塁上IDはその回の残塁で、継続する試合状態ではありません。各半イニングの終了理由・アウト・残塁IDを別途保持します。

## 暫定の進塁・得点

| 結果 | 進塁 |
|---|---|
| 単打／二塁打／三塁打 | 走者全員がそれぞれ1／2／3塁分進む。走力や走塁判断による追加進塁なし |
| 本塁打 | 全走者と打者が生還 |
| 四球／死球 | 打者一塁、押された走者のみ進む。満塁なら押し出し1点 |
| 三振／ゴロアウト／フライアウト | 打者のみ1アウト。走者を保持 |

得点者は進塁前の三塁→二塁→一塁→打者の順に記録します。すべての得点を得点者本人・打者の打点・相手先発投手の失点へ一度ずつ加算します。失策がない現段階では全失点＝自責点です。

サヨナラの非本塁打は勝越点で止めます。決定規則の下では、勝越走者が本塁へ達するまでの塁数に進塁を短縮し、安打種別も短縮した塁数で記録します。例：同点満塁で二塁打相当を抽選しても、三塁走者が1塁分進んだ時点で終了するため単打・1打点です。ログには`drawnOutcome`と記録上の`outcome`の両方を残します。サヨナラ本塁打だけは全得点を計上します。

これは高度な走塁を実装する前の決定規則で、現実の走者ごとの進塁判断を再現するものではありません。併殺・犠飛・犠打・盗塁・失策等のイベントを発生させません。

## 暫定の確率・球数

係数はすべて`src/game/match/config.ts`に分離しました。確定した9回／12回等の`matchRules`と分けています。

各打席で投手の所持球種を等確率に1つ選び、その球種別の球威・制球・変化量を使います。打者は投手の投げ方に対応した対右／対左ミートを使い、同じ側の打者に小さな補正を加えます。両打ちは相手投手と逆の打席に入る仮定です。

- 安打の基準確率は1打席あたり0.23。ミート・球威・変化量・球速・制球・左右を直接反映し、0.16〜0.31に制限します。
- 四球は基準0.085、制球と選択球種の制球で0.035〜0.13。死球は基準0.008、制球で0.004〜0.016。
- 三振は基準0.20、ミート・球速・球威・変化量・左右で0.12〜0.31。
- 安打確率の内訳として本塁打（基準0.028、パワー・弾道・球威）、二塁打（0.041、パワー）、三塁打（0.004、走力）を計算し、残りを単打とします。
- 残りの確率をゴロ・フライアウトへ分け、弾道を反映します。すべての結果は非負で合計1となることを極端な能力でも検証します。

選手の総合能力値や特殊能力、非公開情報は作成・参照しません。現在能力の個別項目から打席確率への係数だけを適用します。守備・疲労・調子・球場等は未反映です。

推定球数は結果別の整数範囲から試合用PRNGで選びます。

| 結果 | 推定球数 |
|---|---|
| 単打・二塁打・三塁打 | 2〜6 |
| 本塁打 | 1〜6 |
| 四球 | 4〜7 |
| 死球 | 1〜3 |
| 三振 | 3〜7 |
| ゴロ・フライアウト | 1〜6 |

1球ごとのシミュレーションではありません。先発が最後まで投げ、球数で降板・疲労を発生させません。

## 結果とログ

`MatchResult`は以下を返します。

- 勝利球団IDまたはnull（引き分け）、総得点、イニング別得点。
- 裏を未実施ならnull、実施した無得点なら0。
- `endReason`：`regulation`／`extraInnings`／`walkOff`／`twelveInningDraw`。
- 全出場打者の打撃成績。既存`BattingStats`に単打数`singles`を加え、打席・打数・長打内訳・得点・打点・四死球・三振を記録。未実装プレーの項目は0。
- 両先発の投手成績。既存`PitchingStats`に与死球`hitBatters`と推定球数`pitches`を追加。投球回は整数アウト数です。
- 交代がないため勝利・敗戦は勝敗球団の先発に付け、引き分けでは付けません。セーブ・ホールドは0。
- 各打席の回・表裏・球団・打順・打者・投手・抽選結果／記録結果・前後のアウト／走者／得点／次打順・得点者・打点・推定球数。
- 半イニングの得点・アウト・残塁と終了理由。
- `random`：試合シード・初期状態・終了状態、`engineVersion: 1`。

ログは文字列連結ではなくIDと構造で返すため、将来のテキスト画面は既存の球団名・選手名辞書へ対応付けて表示できます。現在は観戦UIや正式な試合記録を作りません。

## 再現性と異常終了

既存のMulberry32 `SeededRandom`を試合ごとに新規作成します。標準抽選は所持球種選択・結果抽選・推定球数の順に使用し、注入時は結果抽選の代わりに注入関数を呼びます。正式セーブの乱数インスタンス・状態とは共有しません。同一の選手・打順・出場可能者・所属・試合シード・エンジン版で完全再現します。終了PRNG状態から乱数列を続けることはできますが、試合途中の保存・再開APIは今回提供しません。

`Math.random()`、日時、DB、Reactを参照しません。元の配列・能力・契約・成績・所属に書き込みません。

非有限能力・不正シード・不正スタメンは開始前に拒否します。半イニング200打席の安全弁（暫定の計算保護値）を設け、アウトが出ない注入や極端な乱数列は`MatchSimulationError`で中断します。野球ルール上の打席上限ではなく、上限時にアウト・引き分け・勝敗を捏造しません。外部から渡す注入関数自体は同期的に完了する必要があります。
