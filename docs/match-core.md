# Phase 3C-2：投手交代・救援登板・責任走者（engineVersion 7）

基準mainは`ac9ae6d`（Phase 3C-1マージ済み）。この節が現在の差分仕様で、以下は旧版の履歴です。投手交代は明示的なコールバック指示だけで実行し、未指定なら従来どおり先発を続投させます。schemaVersion 3、IndexedDB、選手保存型・能力・役割・fitness・生成、正式セーブのPRNGは変更していません。

## 交代タイミング・API

`MatchOptions.resolvePitchingChange(context)`を追加しました。各打席前に最大1回、**投手交代→盗塁判断→打席処理**の順で呼びます。イニング開始・途中、0〜2アウト、走者あり、延長も同じです。盗塁死で第3アウトならそのまま攻守交代し、終了した半イニングで交代を追加しません。同じ打席前に再帰的に交代判断しません。打席途中の交代・3人打者最低対戦等の追加ルールは導入していません。

```ts
simulateMatch(input, {
  resolvePitchingChange: context => {
    // テストで明示した条件。製品側の自動継投AIではない。
    if (context.before.inning === 6 && context.currentStats.starts === 1 && context.availablePitchers.length) {
      return { action: "change", pitcherId: context.availablePitchers[0].id };
    }
    return { action: "continue" };
  },
});
```

文脈には`before`（回・表裏・アウト・塁・スコア・次打順）、攻守球団ID、`batter`、`currentPitcherId`、`currentFatigue`、`currentStats`、`availablePitchers`、`responsibilities`、`eventIndex`、`timelineIndex`を含みます。`eventIndex`は次の完了打席番号、`timelineIndex`は実際の時系列配列位置です。盗塁死で打席が未完了のまま交代した場合も、打席番号は増えません。

当日の`availablePlayerIds`は開始前に既存の登録・支配下・ベンチ人数・外国人枠検証を行います。交代候補はそこから同球団の投手だけを選び、現在投手・既に降板した投手を除外します。役割`starter/closer/setup/middle/long`と現在能力をコピーして渡します。救援適性0、役割が先発の投手も、当日条件を満たせば救援起用できます。能力・役割を変更しません。

不明な指示、候補外ID、野手・他球団・ベンチ外・未登録・育成選手への交代、現在投手・降板投手への再登板、余分な指示フィールド、非関数オプションは明示拒否します。コールバックの状態・成績・能力・球種・候補配列・責任走者は凍結コピーで、元Playerや非公開成長情報は渡しません。続投判断のイベントは生成しません。

## 投手別成績・疲労

先発は登板1・先発1、救援は指示を受けて初めて登板1・先発0の成績を作ります。未登板の控えには成績・疲労状態を作りません。試合前に指定した先発を最初の投球前に交代した場合も、先発の登板1・先発1・0球を保持する今回のモデルです。

投球アウト・被安打・被本塁打・四死球・三振・球数は、そのプレーを実際に担当した投手へ加算します。盗塁死のアウトと第3アウト時の追加1球も、その時点で登板している投手へ記録します。失点・自責点だけは責任走者の投手へ配分するため、登板中の投手と異なる場合があります。

各投手の基礎能力・成績・疲労を分離し、新投手は0球・疲労0から開始します。前投手の疲労を引き継がず、交代後の打席には新投手の有効能力を渡します。降板投手の球数・疲労はそのまま保持します。先発・救援適性を疲労式へ追加せず、Phase 3C-1の疲労係数・推定球数ルールを維持しました。

## 責任走者・失点・暫定自責点

`RunnerResponsibility`は`{token, playerId, responsiblePitcherId}`です。出塁単位のトークンには試合内の完了打席番号を文字列化して使い、同じ選手が一巡して再出塁しても区別します。HR打者も独立したトークンで記録します。打者アウトに架空の出塁を作りません。

出塁時の投手を責任投手として固定し、交代で一括変更しません。四球・死球・安打・失策による出塁はすべて同じ経路で対応させます。盗塁・追加進塁ではトークンを保ち、生還・走塁死・盗塁死で活動中の対応を終了します。残塁したトークンも半イニングをまたいで引き継ぎません。

打席の`scoredRuns`は得点者の順に責任情報を返し、投手失点をその責任投手へ1回だけ加算します。`scoredPlayerIds`・個人得点・打点は従来どおりです。例：Aの四球走者がBの二塁打による追加進塁で生還すれば、Aに失点、Bに被安打、打者に安打と打点を記録します。A・Bの走者とCのHR打者が同時に生還すれば、失点をA・B・Cへ各1点配分します。押し出しでも生還走者の責任を使います。

`EarnedRunReconstruction`は従来の失策なし仮想イニングと実得点トークンの照合を維持し、`earnedRunsByPitcherId`で一致したトークンの責任投手へ自責点を配分します。失策走者を自動的に自責とせず、仮想第3アウト以降を再構成しません。盗塁・追加進塁・走塁死の再適用条件も維持しています。実際に得点したトークンだけを照合するため、各投手で0≦自責点≦失点、守備側投手の失点合計＝相手得点を保ちます。

交代時の`currentStats`はその時点のスナップショットです。未終了の半イニングの自責点は、その時点までの再構成値を含む暫定値です。降板後に責任走者が生還すれば最終失点・自責点は増えるため、交代ログの成績を最終成績として扱いません。最終値は`pitchingByPlayerId`です。

自責点は引き続き`reconstructedInningApproximation`で、正式記録員の裁定ではありません。打者走者の入れ替わり・走者交代・責任投手の特例裁定は未実装で、新しい仮定を追加していません。失策で仮想塁・アウトが異なる場合の走塁再適用制約も以前のままです。

## 登板履歴・構造化ログ・個人勝敗

- `MatchResult.pitchingChanges`に交代だけのイベント配列を追加。`timeline`には`{type: "pitchingChange", event}`を挿入します。既存の打席／盗塁配列の意味・番号は維持します。
- 交代イベントは回・表裏を含む`before/after`、交代前後ID、降板投手の成績・球数・疲労、救援の初期疲労、当時の責任走者、`reason: "explicitInstruction"`を保持します。塁・アウト・スコア・打順は変更せず、球数とアウト数も0です。
- 打席・盗塁イベントの`responsibilities`には処理後に塁上にいるトークンの責任情報を追加しました。打席の`scoredRuns`と、従来の移動・得点者ログを組み合わせて、出塁・移動・生還・アウトを追えます。
- `pitcherAppearances`は投手ID・球団ID・元の役割・先発の真偽・登板／降板時のSituationとtimeline位置を保持します。先頭は両先発、救援は登板順で追加し、実際の時系列は`entryTimelineIndex`／`exitTimelineIndex`で照合します。最後の投手の降板欄はnullです。
- `pitchingDecision.status`は、両先発だけなら従来の勝敗を記録する`completeGame`、そのまま引分なら`draw`です。1回でも交代があれば`unadjudicated`（reason=`multiplePitchers`）とし、全投手の勝利・敗戦・セーブ・ホールドを0のままにします。チーム勝敗と得点は確定します。未裁定の0は正式裁定済みの個人成績として使用しません。

将来の正式勝敗裁定に必要な、各得点時のリード推移（打席前後スコア）、得点者の責任投手、登板履歴、先発投球アウト数を保持します。今回、複数投手の正式な勝敗・セーブ・ホールドの裁定は先行実装しません。

# Phase 3C-1：投手スタミナ・登板中疲労（engineVersion 6）

基準mainは`d835c60`（Phase 3B-3Bマージ済み）。この節が現在の差分仕様です。以降の節は旧版の履歴です。先発1人ずつで試合を完了する構造を保ち、交代・救援登板は追加していません。schemaVersion 3、IndexedDB、既存選手保存型・能力・生成、fitness、正式セーブのPRNG・成績は変更しません。

## 疲労計算と暫定係数

`src/game/match/fatigue.ts`の純粋関数`pitcherFatigue(stamina, pitches)`は、保存スタミナとその投手の確定累積推定球数から疲労を返します。乱数・日時・fitness・先発／救援適性は参照しません。全係数は`pitcherFatigueConfig`へ分離した校正前の仮定です。

- 疲労開始球数＝45＋スタミナ×0.65（スタミナ0なら45球、50なら77.5球、100なら110球）。この球数までは疲労0です。
- 疲労度＝(累積球数−開始球数)÷60×100を0〜100へ制限。スタミナが高いほど同じ球数で疲労が小さくなります。
- 能力低下段階＝ceil(疲労度÷25)。疲労0は段階0、0超〜25は1、25超〜50は2、50超〜75は3、75超〜100は4です。
- 最大低下量：球速4km/h、制球10、全球種の球威8、球種制球10。各段階では最大量の段階÷4を差し引きます。途中の有効能力には小数値を許容します。
- 球速は最低1km/h（既存入力の許容下限）、0〜100能力は最低0へ制限。変化量は0〜7の元の整数を維持します。スタミナ・先発／救援適性も元の値を維持します。

例：100球時のスタミナ0は疲労91.67・段階4、スタミナ100は疲労0・段階0です。すべての有効能力は、検証済みの基礎能力の試合用コピーから毎回作成し、前打席の有効能力へさらに低下を重ねません。投げていない半イニングに球数・疲労を回復／リセットしません。試合開始時は両先発とも0球・疲労0です。

負数・非整数・非有限・安全整数範囲外の球数、0〜100整数でないスタミナ、0〜100有限値でない固定疲労は例外で拒否します。非有限・範囲外の基礎投球能力も拒否します。

## 確率への反映と更新順序

投手IDごとに基礎能力を保つ`pitchers`と、現在の`fatigueByPitcherId`を分離しました。球数の正本は既存の`pitchingByPlayerId[id].pitches`です。

1. 打席前の盗塁判断を従来どおり最大1回実行します。成功・第3アウト以外の盗塁死・不実施の追加球数は0なので疲労状態もそのままです。
2. 盗塁死の第3アウトでは追加1球を投手成績へ加え、その確定球数から疲労を更新して攻守交代します。打席の抽選も打順更新もせず、次回の同じ投手の打席前状態へ球数・疲労を引き継ぎます。
3. 続く打席には**その時点までに確定した球数**の有効投手を渡します。既存の`drawPlateAppearance`がその投手の有効球種から抽選し、`outcomeProbabilities`が有効球速・制球・球威・球種制球を使用します。打撃能力・確率式・守備・走塁・盗塁ルールは変更しません。
4. 打席結果・守備・進塁等が確定してから従来の推定球数を加算し、次の疲労状態を基礎能力から計算します。その打席でまだ投げていない球数を判定前に加えません。

したがって累積球数＝完了打席の推定球数合計＋盗塁死第3アウトの追加球数合計です。盗塁と打席で同じ球を二重加算しません。疲労計算自体は乱数を消費しません。エンジン版6で同じ入力・シード・決定的注入なら完全再現し、版5との結果一致は保証しません。

## APIと構造化ログ

- `pitcherFatigue(stamina, pitches)`：球数、スタミナ、開始球数、疲労度、段階を返す凍結された純粋計算結果。
- `applyPitcherFatigue(basePitcher, fatigue)`：指定した固定疲労から有効`MatchPitcher`を返す純粋関数。疲労0／100を固定し、他能力や乱数と分離した確率テストに使用できます。入力は常に基礎能力を渡します。
- `pitcherFatigueState(basePitcher, pitches)`：上記を組み合わせ、`pitcherId`、累積球数、疲労・段階・開始球数、`effectivePitcher`、`adjustments`を返します。`adjustments`は基礎能力から差し引く暫定量です。下限に達した能力の実差分は基礎能力と`effectivePitcher`で照合します。
- 打席と盗塁の各イベントに`pitcherFatigue: {before, after}`を追加しました。前後状態に投手ID・確定球数・疲労・有効能力・補正があり、打席の`before.effectivePitcher`が実際に判定に用いた能力です。盗塁判断自体の確率には投手疲労を新たに反映しません。
- `MatchResult.pitcherFatigueByPlayerId`に登板した各投手の最終状態を格納します。今回の登板者は先発2人だけです。状態をチーム共通にせず、次Phaseの継投時にも投手ID単位で扱える構造です。
- `PlateAppearanceContext.pitcher`は基礎値から疲労を反映した有効投手になります。`pitcherFatigue`も追加し、固定打席注入から判定時の状態を検証できます。能力・球種・疲労状態は凍結コピーで、元Playerや非公開成長情報・fitnessは渡しません。
- `events`、`stealingEvents`、`timeline`の役割・番号・時系列は維持します。打席注入で結果を固定した場合も球数・疲労ログは通常どおり更新します。

既存の投手アウト・失点・暫定自責点再構成・勝敗の計上規則は維持します。自責点は引き続き`reconstructedInningApproximation`という暫定値で、正式な記録員裁定ではありません。

# Phase 3B-3B：盗塁・盗塁死・打席間イベント（engineVersion 5）

基準mainは`77e6fab`（Phase 3B-3Aマージ済み）。この節が現在の差分仕様です。以降は旧版の履歴です。schemaVersion 3、IndexedDB、既存選手データ・保存型・生成、正式セーブのPRNG、画面・正式シーズン成績は変更していません。

## 判定タイミングと対象

各打席の結果を抽選する**前**に盗塁判断を最大1回行います。一塁→二塁、二塁→三塁のみで、出発塁に走者がいて目標塁が空、0〜2アウトが必要です。満塁や三塁走者だけの状態では試行しません。同時に複数走者を動かしません。候補の選択関数は試行確率×成功確率の最大、同値なら先行走者を選びます。現在の隣接塁・占有条件では「一塁走者が二塁を狙える」と「二塁走者が三塁を狙える」は同時には成立しません。

盗塁成功は走者だけを次塁へ移し、走者本人の`stolenBases`を1加算します。盗塁死は走者を除去し、本人の`caughtStealing`と投手アウトを1加算します。いずれも打席・打数・打順・安打・打点・得点を加算しません。第三アウトに達しなければ成功／失敗後とも同じ打者の打席を実行し、その打席前に再度盗塁を判定しません。盗塁死が第3アウトなら打席の抽選自体を行わず直ちに攻守交代し、次の攻撃は未完了の打者から開始します。12回裏でも同じ規則で試合を終了できます。

打席内の追加進塁と送球による走塁死は既存処理を維持し、`stolenBases`／`caughtStealing`へ計上しません。捕手の盗塁阻止は安打阻止・失策の守備機会集計にも加えません。捕手は実スタメンの`position: C`から選び、その選手の肩力・スローイング・`positionAptitudes.C`を使用します。主守備位置が捕手でも当日の起用が別位置なら参照しません。

## 暫定確率・方針係数

`stealingConfig`へ係数を集約しました。以下は校正前の仮定で、能力の中心は50です。総合守備値・独立した捕手リード・特殊能力は作りません。

- 試行基準：二塁への盗塁0.055、三塁への盗塁0.018。
- 試行確率＝〔基準＋(走力−50)×0.0004＋(盗塁能力−50)×0.0006−(捕手肩力−50)×0.00012−二死なら0.006〕×方針倍率。0.002〜0.22に制限します。倍率0の場合は試行確率0。
- 試行時成功確率＝0.72＋(走力−50)×0.0018＋(盗塁能力−50)×0.0022−(捕手肩力−50)×0.0015−(捕手スローイング−50)×0.001−(捕手適性−50)×0.0008−三盗なら0.08。0.20〜0.98に制限します。

走力・盗塁能力を個別に上げると試行／成功の両方が有利になり、捕手の肩力・スローイング・適性を個別に上げると成功率が下がります。方針倍率は現状1で、純粋な確率関数の引数としても指定できます。将来のチーム盗塁積極度への接続点で、今回UI・正式設定データ・戦術AIは追加していません。

## 推定球数の暫定規則

1球単位の投球やカウントは導入しません。盗塁成功・第3アウト以外の盗塁死の球は、続く完了打席の既存推定球数に含むものとし、盗塁イベントの**追加球数**は0です。不実施・候補なしも0です。

盗塁死が第3アウトとなって打席が未完了の場合だけ、`interruptedPlateAppearancePitches: 1`を投手球数へ加算し、盗塁ログにも1を記録します。打席イベントを生成しないため、同じ球数を二重計上しません。総球数＝完了打席の推定球数合計＋盗塁イベントの追加球数合計です。実際の投球列を再現するものではありません。

## 自責点の再構成

既存の`EarnedRunReconstruction`へ盗塁結果を反映します。実走者IDから現在の出塁トークンを解決し、失策なし仮想イニングにも同じトークンが同じ元塁にあり、移動先が空いているときだけ、成功による移動または盗塁死による除去・アウトを再適用します。失策でしか存在しない走者を仮想塁へ新しく生成しません。仮想3アウト以降は処理せず、再抽選もしません。盗塁死した実走者の出塁対応は削除し、一巡後に同じ選手が出塁しても別トークンで扱います。

自責点は引き続き`reconstructedInningApproximation`という**暫定値**です。実得点トークンと仮想得点トークンの照合により0≦自責点≦失点を維持し、投手失点＝相手得点を保ちます。失策で元塁や占有が異なり同じ盗塁が成立しない場合は再適用しません。正式な記録員裁定・仮想戦術や別投球列の完全再現ではありません。

## API・イベント互換性

- `MatchOptions.resolveStealing(context)`を追加。各打席前に1回、候補なしでも呼びます。`{action: "hold"}`、`{action: "safe", runnerId}`、`{action: "out", runnerId}`を注入できます。候補外走者・本盗・占有塁への試行、不明な結果・余分なフィールド・非関数は明示拒否します。
- `StealingContext`は次の完了打席番号`plateAppearanceIndex`、打席前状態、未完了打者ID、投手ID、実捕手の現在能力、候補走者のID／speed／stealing／from／to／適用確率を持つ凍結コピーです。非公開成長情報・元Playerは渡しません。
- `stealingProbabilities(runner, catcher, from, outs, attemptMultiplier = 1)`を公開。試行／試行時成功の確率を別々に返します。
- `MatchResult.events`は従来どおり**完了した打席だけ**です。打席内`index`、守備／追加進塁ログも維持します。盗塁で打席番号は増えません。
- `MatchResult.stealingEvents`へ専用ログを追加。独自の`index`、前後の塁・アウト・得点・次打順、打順番号、捕手／候補／選択走者、`action`、`attempted`、`movements`、アウト数、追加球数、`plateAppearanceCompleted: false`、`endedHalfInning`を保持します。`reason`は`noEligibleRunner`／`hold`／`attempt`で、試行しない判断も区別します。盗塁死の移動は`outKind: tag`です。
- `MatchResult.timeline`は`{type: "plateAppearance", event}`または`{type: "stealing", event}`の配列で、配列順が時系列です。各eventは既存配列内の同じイベントを参照します。前後状態を追う呼び出し側は、打席配列間の連続性ではなくこの時系列を使います。成績集計では両配列を再度timeline分と重複加算しません。
- 固定`resolvePlateAppearance`があり`resolveStealing`がない場合は盗塁判断・乱数消費を省略し、既存の固定結果規則テストを維持します。通常シミュレーションでは自動判定を有効にします。

乱数は既存の試合用`SeededRandom`だけを使用します。対象候補なしでは盗塁乱数を消費せず、候補選択後に試行1回、試行する場合だけ成功1回を抽選し、その後に打席・守備・追加進塁・推定球数を従来の順で実行します。固定盗塁注入は盗塁乱数を消費しません。エンジン版は5で、同一入力・シード・版・決定的注入で完全再現します。版4との乱数列・結果の一致は保証しません。

# Phase 3B-3A：追加進塁・走塁死・外野送球（engineVersion 4）

基準はmain `b758d4a`（Phase 3B-2）。この節が現在の差分仕様です。後続の節は各版の履歴で、現在の「追加進塁なし」「肩力非参照」等の説明には適用しません。schemaVersion 3、IndexedDB、既存選手の保存型・生成・正式PRNG、UI・打撃確率は変更していません。

## 対象・判定順

守備による安打阻止・失策判定が終わってから、残った単打／二塁打へ走塁判定を適用します。単打で一塁→三塁、単打で二塁→本塁、二塁打で一塁→本塁だけが対象です。打者自身は通常の安打到達までで、追加塁を狙いません。安打阻止された打球、失策出塁、犠飛、犠打、併殺、HR、四死球には追加進塁を適用しません。

通常進塁先を全員分確保し、三塁→二塁→一塁の先行順に解決します。追加進塁先の三塁に先行走者が残るなら試行せず、通常進塁で終了します。先行走者が本塁へ進む／本塁でアウトになると、後続は空いた三塁を狙えます。判定結果は`hold`（不実施）、`safe`（追加進塁成功）、`out`（送球によるタッグアウト）の3つです。走塁死では通常到達塁から走者を除き、打者安打・打数・安打種別を維持し、投手アウト数にだけ走者アウトを加えます。盗塁死成績には加えません。

同一打球の送球担当は共通です。既存守備ログの担当が外野なら同じ選手を使い、それ以外はLF:CF:RF＝1:2:1で外野送球担当を選びます。内野を抜けた打球の外野回収を簡略化した暫定モデルで、中継・正確な打球方向・飛距離は再現しません。担当ID・肩力・スローイング・適性は**実際のスタメンの起用位置**から取得し、主守備位置・DH・控えの能力を流用しません。安打阻止の守備機会・失策集計と外野送球は別で、送球アウトを安打阻止数や失策へ加えません。

## 暫定係数

`src/game/match/config.ts`の`baserunningConfig`へ集約しました。基準能力50で、全係数は校正前の仮定です。

- 試行確率の基準：単打一塁→三塁0.30、単打二塁→本塁0.52、二塁打一塁→本塁0.48。
- 試行確率＝基準＋(走力−50)×0.004−(肩力−50)×0.001＋二死なら0.12＋ゴロなら0.04。0.03〜0.92へ制限。
- 試行時のアウト確率＝0.12−(走力−50)×0.0015＋(肩力−50)×0.002＋(スローイング−50)×0.0006＋(起用位置適性−50)×0.0004＋本塁目標なら0.035−二死なら0.02−ゴロなら0.02。0.015〜0.45へ制限。
- 打球種別は既存守備判定のground／flyを使用。守備を省いた固定打席注入では、対象走者がいる単打だけ55%でground、残りfly、二塁打はflyとします。

高走力では試行しやすくアウトになりにくく、高肩力では試行を抑えつつ試行時のアウト確率が上がります。スローイングと位置適性は送球アウト確率に個別反映します。総合守備能力・特殊能力は作りません。

## 第3アウト・得点・打点・自責点

打席ログと`PlayTransition`の`playSequence`は、得点／アウト成立の時間順を保持します。先行走者の通常生還→先行走者の本塁追加進塁→後続走者の追加進塁の順に処理する暫定のタイムプレーモデルです。実際の走行秒数や送球時間は計算しません。`scoredBeforeThirdOut`で第3アウトより前の得点だけを認め、フォース／打者走者の一塁到達前アウトが第3アウトなら先行得点も無効にします。追加進塁によるアウトはすべて`tag`で、フォースではありません。

例：二死満塁の単打で三塁走者が先に生還し、二塁走者が本塁タッグアウトで第3アウトなら1得点・1打点が有効です。一塁走者の追加進塁は抽選せず、通常到達の二塁に残して残塁扱いにします。先行走者が本塁アウトになった後に後続の得点を生成しません。複数走者アウトでも累計3アウトで止め、次打席を実行しません。

サヨナラ非HRの通常進塁と安打分類は従来の必要塁打規則を保持します。追加進塁で勝越点が入った場合も直ちに終了し、後続への追加進塁・送球アウトを抽選しません。勝越前に成立したアウトだけを記録します。追加進塁で生還しても打者が余分な塁を得ることはありません。

安打による追加生還は打点対象、失策プレーによる生還は従来どおり0打点です。投手失点＝相手得点、個人得点合計＝チーム得点、投手アウト＝全打者／走者アウトを共通の遷移から集計します。

自責点は引き続き`reconstructedInningApproximation`という**暫定値**です。出塁トークンで実走者と失策なし仮想走者を対応させ、同じ出発塁と追加目標で成立する走塁結果だけを再適用します。走塁死も仮想アウトに加え、仮想3アウト以降は処理せず、乱数の再抽選はしません。失策により塁や成立条件が異なる場合、新しい積極走塁は仮定せず通常進塁とします。実得点トークンと仮想得点トークンの積集合なので0≦自責点≦失点を保ちます。正式な記録員裁定・中継送球や仮想戦術の完全再現ではありません。

## API・構造化ログ・再現性

- `MatchOptions.resolveBaserunning(context)`を追加。対象走者だけに呼び、`hold | safe | out`を注入可能です。それ以外や非関数のオプションは明示的に拒否します。塁衝突・3アウト・サヨナラで判定不要なら呼びません。
- `BaserunningContext`は走者ID、出発塁、追加目標、安打種別、アウト数、打球種別、走力、送球担当のID／位置／arm／throwing／起用位置適性を持つ凍結コピーです。非公開成長情報・元Playerは渡しません。
- `baserunningProbabilities(context)`を公開し、試行／試行時アウトの確率を返します。
- `movements[].extraAdvance`に文脈・`action`・`attempted`・`outPlayerId`・適用確率を保持します。候補走者には`extraAdvanceTarget`と`extraAdvanceAttempted`も保持し、判定を省いた場合は`advanceBlocked: occupied | thirdOut | walkOff`で理由を明示します。既存の`playerId/from/to/outKind`と打席前後の塁・アウト・得点は維持します。
- `outKind`に`tag`を追加。`playSequence: PlayMoment[]`はIDとscore／out・アウト種別の配列で、配列順が成立順です。通常の併殺・犠飛等にも付与します。
- 通常の試合専用`SeededRandom`のみ使用。既存打席→守備→必要な打球種別・外野担当決定→走者ごとの試行抽選→試行時だけアウト抽選→推定球数の順で消費します。外野担当は1打球1回、対象走者がいなければ走塁乱数を消費しません。`Math.random()`・正式PRNGは使いません。
- 固定打席注入があり`resolveBaserunning`がない場合、従来の決定的進塁を維持します（守備注入の有無によらない）。走塁の固定テストには両方を渡します。守備の固定試験には従来どおり`resolveDefense`を併用できます。
- エンジン版4。同一入力・シード・版・決定的な注入で完全再現します。版3との乱数消費・試合結果の完全一致は保証しません。

# Phase 3B-2：守備・失策（engineVersion 3）

## 守備の対象と暫定確率

介入対象は通常の`groundOut`・`flyOut`、安打性の`single`・`double`・`triple`です。三振・四死球・本塁打、併殺・犠飛・犠打は今回の守備判定から除外します。守備でアウトへ変えた安打性打球は通常アウトとし、追加で併殺・犠飛へ変換しません。従来の打撃・投手・球種の確率計算は維持しています。

守備担当は実スタメンの守備位置→選手IDで引き、主守備位置ではなく**その起用位置の適性**を参照します。DH・投手は担当しません。`defenseConfig`へ打球・位置の重みと係数を集約しました。

- 通常ゴロは内野（1B:2B:3B:SS＝1:2:1:2）。単打性打球は55%ゴロ、残りフライ。二・三塁打性打球はフライ扱い。
- フライはC:1B:2B:3B:SS:LF:CF:RF＝1:1:1:1:1:2:3:2で担当を抽選します。ライナー・正確な方向・飛距離は未実装です。
- 安打阻止確率＝0.015＋(捕球−50)×0.0004＋(当該位置適性−50)×0.00035（0〜0.09に制限）。阻止時は打球に対応する通常アウトへ変更します。
- 捕球失策確率＝0.012−(捕球−50)×0.00012−(適性−50)×0.00010（0.001〜0.045）。
- ゴロの送球失策確率＝0.009−(スローイング−50)×0.00010−(適性−50)×0.00008（0.001〜0.035）。フライで送球失策は抽選しません。

通常アウトでのみ失策を抽選し、安打性打球でのみ安打阻止を抽選します。一度安打阻止した打球へさらに失策抽選は行いません。捕球・送球失策は互いに排他的です。肩力は今回参照せず、総合守備値・OVRを作りません。これらの確率は校正前の暫定値です。

## 失策の進塁・成績とログ

`reachedOnError`は守備判定後の記録結果です。打者は一塁、押し出される走者だけ進み、満塁なら三塁走者1人が得点します。打数を加算し、安打・四死球・投手被安打は加算しません。失策プレーの打点は0です。その後の安打等の通常打点は従来どおり記録します。三塁走者がいる犠打・スクイズは引き続き明示拒否します。

各打席イベントへ`defense`（対象外ならnull）を追加しました。打球種別、守備前結果、担当野手ID／位置／参照した現在能力、安打阻止の真偽、失策の真偽・種類・失策者IDを保持します。守備後の結果、アウト・走者移動・得点者・打点は同じ打席イベントの既存フィールドで照合できます。

結果の`fieldingByPlayerId`はスタメン野手8人ずつの守備集計で、`chances`（今回の介入対象打球の担当回数）、`hitsPrevented`、`errors`、`catchingErrors`、`throwingErrors`を返します。捕殺・補殺・正式な守備機会数の記録ではありません。保存選手の履歴へは反映しません。

## 自責点は暫定再構成値

`earnedRunMethod: "reconstructedInningApproximation"`を結果へ明示し、投手の`earnedRuns`を**暫定の失策なし再構成値**として扱います。正式な記録員裁定ではありません。

各半イニングで別の塁・アウト状態を維持し、失策出塁を元のゴロ／フライアウトへ置き換え、失策がなかった場合の進行を再構成します。仮想3アウト後は打席を追加しません。各出塁に打席固有トークンを付け、実際に生還し、仮想イニングでも生還した同じ出塁だけを自責対象にします。同じ選手が一巡後に再出塁しても区別します。実得点と仮想得点を照合するため、0≦自責点≦失点、投手失点＝相手得点を維持します。

例：無死の失策→本塁打は、失策走者だけ非自責・本塁打打者は自責。二死の失策→本塁打は仮想イニングが終了済みなので両者とも非自責です。失策直後の得点を一律に自責／非自責へ分類しません。

制約：仮想塁状態では成立しない併殺・犠飛・犠打を通常ゴロ／フライアウトへ置き換えます。仮想の采配・別の乱数列・走者ごとの積極走塁は再計算しません。実試合が終了した半イニングの範囲だけを再構成します。公式規則の疑義裁定や走者有利の裁定を完全再現するものではなく、正式シーズン記録への接続時に再設計が必要です。

# Phase 3A：打席単位の単体試合エンジン

`src/game/match/`に、React・IndexedDB・実時間から独立したTypeScriptの試合計算を実装しました。既存のschemaVersion 3、DB構造、選手生成、所属、画面は変更していません。結果は呼び出し元へ返すだけで、日付・正式乱数・選手・今季成績・セーブへ反映しません。

## API

```ts
import { simulateMatch, type MatchInput } from "../src/game/match";

const input: MatchInput = {
  // 呼び出し元で検証・読込済みの選手と所属。engineは保存APIを呼ばない。
  players: save.world.players,
  roster: save.world.roster,
  away: {
    teamId: awayTeamId,
    availablePlayerIds: awayBenchIds, // 明示した当日の出場可能選手
    battingOrder: awayOrder,         // [{playerId, position}, ...] 配列順に1〜9番
    startingPitcherId: awayStarterId,
  },
  home: {
    teamId: homeTeamId,
    availablePlayerIds: homeBenchIds,
    battingOrder: homeOrder,
    startingPitcherId: homeStarterId,
  },
  seed: matchSeed, // 明示した試合専用uint32。正式保存のPRNGを進めない。
};
const result = simulateMatch(input);
```

コード例の`save`などは呼び出し元の変数で、今回UIや保存処理へ接続するコードは追加していません。全12球団の所属整合を既存関数で検証するため、`players`は所属一覧を検証できる全選手データを渡します。試合で利用できる人数は各球団の`availablePlayerIds`で別に限定します。

- `validateMatchInput(unknown)`：不正なら`MatchInputError`。選手の計算対象能力・投打・球種の整数範囲、所属状態、同一球団対戦、ベンチ・打順・守備・先発を同期検証します。正式セーブ全体の検証・移行を代行しません。
- `simulateMatch(input, options?)`：1試合を計算し、完了した`MatchResult`だけを返します。途中状態を保存しません。
- `options.resolvePlateAppearance(context)`：規則テスト用の結果注入。未指定時は能力と`SeededRandom`で抽選します。注入関数は決定的にし、未実装の結果を返すと例外です。
- `outcomeProbabilities(batter, pitcher, pitch)`：検証済みの現在能力と選択球種から9結果の確率を計算する純粋関数。
- `drawPlateAppearance(batter, pitcher, random)`：呼び出し側から渡した試合用PRNGを使用。
- `advanceRunners(bases, batterId, outcome, runsToWin?)`：塁ID配列のコピー、得点者ID、実際の安打種別、打者アウトを返す純粋な進塁処理。

注入コールバックにはホワイトリストでコピー・凍結した現在能力と打席前状態だけを渡します。元のPlayer、契約、過去成績、所属辞書、非公開成長情報は渡しません。打席結果を注入した場合も推定球数には試合用PRNGを使用します。

## 入力の制約

- 両球団は固定12球団の異なる2球団。
- ベンチは既存の`validateBench`を利用し、1軍・支配下・人数・外国人枠・重複・所属を検証します。
- 打順は欠員・重複のない野手9人。8守備位置（C/1B/2B/3B/SS/LF/CF/RF）とDHを各1人。投手は別に1人指定します。
- 打者も投手も当日の出場可能IDに含まれる自球団の選手。2軍・育成は起用不可。
- 位置ごとの適性0を拒否し、1以上を許可する境界は**暫定設定**です。主守備位置以外でも適性があれば許容し、DHに守備適性は不要です。
- 自動スタメン・ベンチ選定はありません。テストだけで、1軍登録者から各位置を明示した固定打順を用意します。

## 確定ルールと試合状態

9回制、両リーグDH、3アウト交代、打順継続、同点なら延長12回まで。12回裏終了時同点は引き分けです。延長の自動二塁走者は置きません。

9回表終了時に後攻がリードしていれば9回裏は未実施とします。9回裏以降は後攻の勝越点で直ちに終了します。先攻リード・同点なら必要な裏を行い、12回裏も同じ規則を適用します。追いついた点だけでは終了しません。

`Situation`は回、表裏、アウト、塁上の選手ID、先後攻得点、両軍の次打者インデックス（0〜8）を保持します。ログの打順番号は1〜9です。攻守交代時だけアウトと塁をリセットし、両軍の打順を保持します。

`finalState`は最終打席直後の状態です。最終アウト後の塁上IDはその回の残塁で、継続する試合状態ではありません。各半イニングの終了理由・アウト・残塁IDを別途保持します。

## 暫定の進塁・得点

| 結果 | 進塁 |
|---|---|
| 単打／二塁打／三塁打 | 走者全員がそれぞれ1／2／3塁分進む。走力や走塁判断による追加進塁なし |
| 本塁打 | 全走者と打者が生還 |
| 四球／死球 | 打者一塁、押された走者のみ進む。満塁なら押し出し1点 |
| 三振／ゴロアウト／フライアウト | 打者のみ1アウト。走者を保持 |

得点者は進塁前の三塁→二塁→一塁→打者の順に記録します。すべての得点を得点者本人・打者の打点・相手先発投手の失点へ一度ずつ加算します。失策がない現段階では全失点＝自責点です。

サヨナラの非本塁打は勝越点で止めます。決定規則の下では、勝越走者が本塁へ達するまでの塁数に進塁を短縮し、安打種別も短縮した塁数で記録します。例：同点満塁で二塁打相当を抽選しても、三塁走者が1塁分進んだ時点で終了するため単打・1打点です。ログには`drawnOutcome`と記録上の`outcome`の両方を残します。サヨナラ本塁打だけは全得点を計上します。

これは高度な走塁を実装する前の決定規則で、現実の走者ごとの進塁判断を再現するものではありません。併殺・犠飛・犠打・盗塁・失策等のイベントを発生させません。

## 暫定の確率・球数

係数はすべて`src/game/match/config.ts`に分離しました。確定した9回／12回等の`matchRules`と分けています。

各打席で投手の所持球種を等確率に1つ選び、その球種別の球威・制球・変化量を使います。打者は投手の投げ方に対応した対右／対左ミートを使い、同じ側の打者に小さな補正を加えます。両打ちは相手投手と逆の打席に入る仮定です。

- 安打の基準確率は1打席あたり0.23。ミート・球威・変化量・球速・制球・左右を直接反映し、0.16〜0.31に制限します。
- 四球は基準0.085、制球と選択球種の制球で0.035〜0.13。死球は基準0.008、制球で0.004〜0.016。
- 三振は基準0.20、ミート・球速・球威・変化量・左右で0.12〜0.31。
- 安打確率の内訳として本塁打（基準0.028、パワー・弾道・球威）、二塁打（0.041、パワー）、三塁打（0.004、走力）を計算し、残りを単打とします。
- 残りの確率をゴロ・フライアウトへ分け、弾道を反映します。すべての結果は非負で合計1となることを極端な能力でも検証します。

選手の総合能力値や特殊能力、非公開情報は作成・参照しません。現在能力の個別項目から打席確率への係数だけを適用します。守備・疲労・調子・球場等は未反映です。

推定球数は結果別の整数範囲から試合用PRNGで選びます。

| 結果 | 推定球数 |
|---|---|
| 単打・二塁打・三塁打 | 2〜6 |
| 本塁打 | 1〜6 |
| 四球 | 4〜7 |
| 死球 | 1〜3 |
| 三振 | 3〜7 |
| ゴロ・フライアウト | 1〜6 |

1球ごとのシミュレーションではありません。先発が最後まで投げ、球数で降板・疲労を発生させません。

## 結果とログ

`MatchResult`は以下を返します。

- 勝利球団IDまたはnull（引き分け）、総得点、イニング別得点。
- 裏を未実施ならnull、実施した無得点なら0。
- `endReason`：`regulation`／`extraInnings`／`walkOff`／`twelveInningDraw`。
- 全出場打者の打撃成績。既存`BattingStats`に単打数`singles`を加え、打席・打数・長打内訳・得点・打点・四死球・三振を記録。未実装プレーの項目は0。
- 両先発の投手成績。既存`PitchingStats`に与死球`hitBatters`と推定球数`pitches`を追加。投球回は整数アウト数です。
- 交代がないため勝利・敗戦は勝敗球団の先発に付け、引き分けでは付けません。セーブ・ホールドは0。
- 各打席の回・表裏・球団・打順・打者・投手・抽選結果／記録結果・前後のアウト／走者／得点／次打順・得点者・打点・推定球数。
- 半イニングの得点・アウト・残塁と終了理由。
- `random`：試合シード・初期状態・終了状態、`engineVersion: 1`。

ログは文字列連結ではなくIDと構造で返すため、将来のテキスト画面は既存の球団名・選手名辞書へ対応付けて表示できます。現在は観戦UIや正式な試合記録を作りません。

## 再現性と異常終了

既存のMulberry32 `SeededRandom`を試合ごとに新規作成します。標準抽選は所持球種選択・結果抽選・推定球数の順に使用し、注入時は結果抽選の代わりに注入関数を呼びます。正式セーブの乱数インスタンス・状態とは共有しません。同一の選手・打順・出場可能者・所属・試合シード・エンジン版で完全再現します。終了PRNG状態から乱数列を続けることはできますが、試合途中の保存・再開APIは今回提供しません。

`Math.random()`、日時、DB、Reactを参照しません。元の配列・能力・契約・成績・所属に書き込みません。

非有限能力・不正シード・不正スタメンは開始前に拒否します。半イニング200打席の安全弁（暫定の計算保護値）を設け、アウトが出ない注入や極端な乱数列は`MatchSimulationError`で中断します。野球ルール上の打席上限ではなく、上限時にアウト・引き分け・勝敗を捏造しません。外部から渡す注入関数自体は同期的に完了する必要があります。
